# フェーズ 10: 案件の完了と、完了済みの表示切り替え

- 全体プラン: [1-gantt-chart-mvp.md](1-gantt-chart-mvp.md)
- 担当: Sonnet 5.5
- ブランチ: `feat/gantt-project-complete`
- 前提: フェーズ 9 が完了している（スキーマの移行と、非表示の案件がある状態での並び替えを扱うため）

## 目的

終わった案件を削除せずに「完了」にして、ガントチャートから隠せるようにする。必要なときは完了済みの案件も表示して見返せるようにする。

- サイドパネル（案件の編集）に「完了にする」ボタンを置く
- 完了した案件は、ガントチャート上で非表示になる（削除はしない。データは残る）
- 画面右上に「完了済みを表示する / しない」の切り替えボタンを置き、完了済みの案件も閲覧できるようにする

## 作業内容

### 1. データ層（完了状態の保存）

- `IProject` に `completedAt: string | null` を足す（完了にした日時。ISO 8601。未完了は `null`）
  - 真偽値ではなく日時にするのは、「いつ完了したか」を後から表示・並べ替えに使えるようにするため。Firestore でも `null` はそのまま保存できる
- `TProjectInput` には含めない（追加した案件は必ず未完了）
- `TProjectUpdate` に `isCompleted?: boolean` を足す（`Partial<TProjectInput> & { isCompleted?: boolean }`）。日時は repository が付ける（`createdAt` / `updatedAt` と同じく、日時を作るのは repository の責務にそろえる）
  - 未完了 → 完了: `completedAt` に今の日時を入れる
  - すでに完了している案件に `true`: `completedAt` を変えない
  - `false`: `completedAt` を `null` に戻す
- `isProject` に `completedAt`（`null` か日時の文字列）の検証を足す。`gantt.guards.test.ts` も更新する
- **スキーマの移行（バージョン 2 → 3）**: `CURRENT_SCHEMA_VERSION` を 3 にし、`SCHEMA_MIGRATIONS` に `2: (storage) => { ... }` を足す。既存の案件はすべて `completedAt: null`（未完了）にする。壊れたデータの扱いはフェーズ 9 の移行と同じ
- repository のテスト（完了・完了済みにもう一度完了・未完了に戻す・移行）を足す

### 2. 表示の切り替え（`showCompleted`）

- 「完了済みを表示するか」の state（`isCompletedVisible` など）を持つフックを作り、`useGanttPage` から公開する
  - 初期値は「表示しない」。**保存しない**（再読み込みすると「表示しない」に戻る）。データではなく見た目の設定で、`IGanttRepository` の対象外のため
- 表示しないときは、完了済みの案件を次のすべてから除く
  - 左のリストの案件の行
  - 右のタイムラインの帯の行
  - 担当者行のまとめ帯（`MemberSummaryBar`）
  - 担当者行の件数の表示（表示している件数を出す）
- 絞り込みは `groupProjectsByMember` の前（または後）に 1 か所でまとめて行い、左右の行がずれないようにする。`memberGroups` の `useMemo` の依存に切り替えの state を足す
- 担当者の削除の確認（「案件 N 件も一緒に削除されます」）は、完了済みも含めた件数のままにする（完了済みも一緒に消えるため）

### 3. 切り替えボタン（`GanttHeader`）

- ヘッダーの右端に置く。押すたびに「表示する / しない」が入れ替わるトグルボタンにし、`aria-pressed` で状態を伝える
  - 文言の例: 「完了済みを表示」。状態が分かるよう、押されているときは見た目を変える（主色の背景など）
  - 完了済みの件数を添える（例: 「完了済みを表示（3）」）。0 件のときも押せるようにしておく
- `GanttHeader` の props に `isCompletedVisible` / `completedCount` / `onToggleCompletedVisible` を足す。表示用の値（文言・クラス名）は `useGanttHeader` で組み立てる

### 4. 完了ボタン（`ProjectSidePanel`）

- **編集のときだけ**、フッターのボタン群（削除・キャンセル・保存）に「完了にする」を足す。完了済みの案件を開いたときは「未完了に戻す」にする
- 押したときの動き
  - フォームの内容も一緒に保存する（「保存」と同じ検証を通し、`updateProject` に `isCompleted` を足して 1 回で保存する）。編集途中の内容が失われないようにするため。検証で失敗したら完了にもしない
  - 保存に成功したらパネルを閉じる
  - 保存中は他のボタンと同じく押せなくし、失敗はパネル内の `submitError` に出す
- 完了済みの案件を編集しているときは、パネルの見出しの近くに「完了済み（10/30）」のような表示を出す

### 5. 完了済みの案件の見た目（表示するとき）

- 左のリスト: 案件名を薄くし、先頭（つかみのアイコンの後ろ）に完了の印（✓ など）を出す
- 帯（`ProjectBar`）・まとめ帯: 透明度を下げて、未完了の案件と区別する
- 完了済みでも、クリックでのサイドパネル・帯のドラッグ・並べ替えは未完了と同じようにできる
- 透明度などの値は `_tokens.scss` にトークンとして足す

### 6. 並び替えとの関係（フェーズ 9 の続き）

- 完了済みを隠しているときに並べ替えると、**見えている案件の中で**並べ替え、隠れている完了済みの案件はその前後関係を保つ
  - 例: 全体が `A, (B 完了), C, D` で `D` を `A` の前へ落とす → `D, A, B, C`
  - 規則: 落とした先の「直後に見えている案件」の前に挿入する。末尾に落としたときは「最後に見えている案件」の直後に挿入する
- この計算を純粋関数（例: `moveProjectAmongVisible(allIds, visibleIds, projectId, toVisibleIndex)`）にしてテストし、結果の全 id を `reorderProjects` に渡す

### 7. テスト

- 型ガード（`completedAt`）、repository（完了・再完了・未完了に戻す・移行）、完了済みの絞り込み、隠れた案件がある状態での並べ替えの計算、ボタンの文言・件数の組み立て（utils に切り出した部分）

## 完了条件

- [ ] サイドパネルの「完了にする」で案件が完了になり、ガントチャートから消える（データは残る）
- [ ] 右上の切り替えボタンで完了済みの案件を表示・非表示でき、表示したときは未完了と見分けられる
- [ ] 完了済みの案件を開いて「未完了に戻す」と、表示しない状態でも再び表示される
- [ ] 完了済みを隠したまま並べ替えても、隠れた案件の前後関係が崩れない
- [ ] 完了の状態が、再読み込みしても残る（切り替えボタンは「表示しない」に戻る）
- [ ] 既存のデータ（スキーマ 2）を読むと、すべて未完了として表示される
- [ ] `pnpm lint` / `pnpm typecheck` / `pnpm test` / `pnpm build` が成功する
