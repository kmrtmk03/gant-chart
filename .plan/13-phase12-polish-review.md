## 目的

MVP として使える状態に仕上げ、全体を通して確認し、別のエージェント（Codex）の目でレビューする。

## 作業内容

### 1. 仕上げ

- 見た目の調整: 余白・帯の色のコントラスト（帯の上の文字が読めるか）。文字の大きさ（最小 16px）はフェーズ 11 で対応済み
- 狭い画面（スマホ）では閲覧できれば可。左のリストの幅を縮め、サイドパネルは画面いっぱいに表示する
- キーボード操作: ボタンとフォームに Tab で移動できる、フォーカスの枠が見える
- 帯に `aria-label`（例: 「案件A 10月3日〜10月12日」）を付ける
- 読み込み中・保存失敗時の表示を見直す
- `README.md` を書く: 概要、必要なもの（Node 24 以上、pnpm 11）、セットアップ手順、`.env.local` の書き方、コマンド一覧

### 2. 全体の検証

- 自動: `pnpm lint` / `pnpm typecheck` / `pnpm test` / `pnpm format:check` / `pnpm build`
- 本番ビルドでの確認: `pnpm build && pnpm start` で Basic 認証（環境変数未設定時はすべて拒否）と PWA のインストールを確認する
- 手動: 全体プラン 7 章「検証計画」のチェック項目をすべて確認する

### 3. コードレビュー（Codex）

- 観点
  - `AGENTS.md` の規約（命名・コメント・フックの設計・型安全）に沿っているか
  - Firestore への移行を妨げる書き方がないか（repository を通さないデータアクセス、`Date` の保存など）
  - Basic 認証の抜け道がないか（`matcher` の除外範囲、環境変数未設定時の挙動）
  - ドラッグ操作（帯のドラッグ・案件の並び替え）のイベントの登録漏れ・解除漏れ
  - スキーマの移行（1 → 2 → 3）で既存のデータが失われないか
- 指摘は重要度の順に並べてもらい、対応するもの・見送るものをユーザーと決めてから修正する
